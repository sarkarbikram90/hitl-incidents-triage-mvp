Ajaia IT Incident Triage Prototype • Single-File Static Architecture
System Limitations & Production Architecture Requirements

This prototype is an interactive frontend demonstration of evidence-backed, human-in-the-loop triage for IT & security incidents. It runs client-side with synthetic sample data. No real systems or credentials are touched.

Prototype Scope & Constraints

  • Zero live credentials, keys, or authentication tokens are stored or used.
  • All decisions, modifications, and audit logs are held in browser localStorage.
  • No external API, LLM endpoint, or SIEM/ITSM webhook is dialed.
  • Do not enter real client PII, confidential secrets, education records, or PHI.

Requirements for Production Implementation

  1. Identity & RBAC: Authenticated sessions with SAML 2.0 / OIDC, strict role separation (L1 Triage vs. L2 Security Specialist vs. SecOps Admin).
  2. Durable Audit Vault: Tamper-evident write-once storage (e.g. AWS S3 Glacier Object Lock) with cryptographic hashing of analyst approvals.
  3. Secret & PII Redaction: Automated regex and NLP sanitization pipeline to redact tokens, passwords, SSNs, and private data before LLM inference.
  4. Connector-Scoped Permissions: Fine-grained least-privilege tokens for ticketing (Jira/ServiceNow), IdP (Okta), and cloud providers (AWS/GCP).
  5. Idempotent Orchestration: Safe retry logic, dry-run simulation gates, and automatic fallback rollbacks.
